## 1. テーブル定義書

### tasks(タスク)

| カラム | 型 | NULL | 既定値 | 説明 |
|---|---|---|---|---|
| id | BIGINT (IDENTITY) | 不可 | 自動採番 | 主キー |
| title | VARCHAR(100) | 不可 | — | タイトル |
| description | VARCHAR(500) | 可 | — | 説明 |
| done | BOOLEAN | 不可 | FALSE | 完了フラグ |
| priority | VARCHAR(10) | 不可 | 'MEDIUM' | 優先度。`HIGH`(高)/`MEDIUM`(中)/`LOW`(低)のいずれか(CHECK制約 `chk_tasks_priority`) |
| due_date | DATE | 可 | — | 期限。NULLは期限なし |
| created_at | TIMESTAMP WITH TIME ZONE | 不可 | CURRENT_TIMESTAMP | 登録日時 |
| completed_at | TIMESTAMP WITH TIME ZONE | 可 | — | 完了日時。NULLは未完了、または完了日時不明(V5以前に完了済みだったタスク)。値があるのは `done = TRUE` の場合のみ(CHECK制約 `chk_tasks_completed_at`) |
| category_id | BIGINT | 可 | — | カテゴリ。NULLはカテゴリなし。categories.id への外部キー(`fk_tasks_category`、`ON DELETE SET NULL`=カテゴリ削除時はカテゴリなしに戻る) |

- 対応マイグレーション: `V1__create_tasks.sql`(定義)、`V2__insert_seed_tasks.sql`(初期データ)、`V3__add_priority_to_tasks.sql`(優先度追加。既存タスクは `MEDIUM`)、`V4__add_due_date_to_tasks.sql`(期限追加。既存タスクは期限なし)、`V5__add_completed_at_to_tasks.sql`(完了日時追加。既存タスクは NULL)、`V6__create_categories.sql`(カテゴリ追加。既存タスクはカテゴリなし)
- インデックス: 主キー、`idx_tasks_category_id`(category_id。カテゴリでの絞り込みと、カテゴリ削除時の SET NULL で使う)

### categories(カテゴリ)

| カラム | 型 | NULL | 既定値 | 説明 |
|---|---|---|---|---|
| id | BIGINT (IDENTITY) | 不可 | 自動採番 | 主キー |
| name | VARCHAR(30) | 不可 | — | カテゴリ名。重複不可(一意制約 `uq_categories_name`) |

- 対応マイグレーション: `V6__create_categories.sql`(定義)、`V7__insert_seed_categories.sql`(初期データ: 仕事・私用・勉強)
- インデックス: 主キー、一意制約 `uq_categories_name` のインデックス

## 2. バリデーション仕様

| 対象 | ルール | 実装箇所 |
|---|---|---|
| title | 必須(空白のみ不可)、100文字以内 | TaskRequest(Bean Validation) |
| description | 500文字以内 | 同上 |
| priority | `HIGH`/`MEDIUM`/`LOW` のいずれか。未指定(null)は `MEDIUM` として扱う | `Priority` enum(型変換)+ `TaskRequest.priorityOrDefault()`。DB側もCHECK制約で保証 |
| dueDate | 任意。`yyyy-MM-dd` 形式の日付。過去日も可(期限切れタスクを編集できるようにするため) | `LocalDate`(型変換) |
| categoryId(タスク) | 任意。登録済みのカテゴリのID。存在しないIDは400 | `TaskService`(存在確認)。DB側も外部キーで保証 |
| sort(A-01のクエリ) | `ID`/`PRIORITY` のいずれか。未指定は `ID` | `TaskSort` enum(型変換) |
| categoryId(A-01のクエリ) | 任意。数値。存在しないIDは空の一覧(エラーにしない) | `Long`(型変換) |
| name(カテゴリ) | 必須(空白のみ不可)、30文字以内。前後の空白を除いた値で登録し、既存と同じなら409 | CategoryRequest(Bean Validation)+ `CategoryService`(重複確認)。DB側も一意制約で保証 |
| フロント側 | タイトル・カテゴリ名が空の間は追加ボタン非活性、maxLengthで文字数制限。優先度・並び順・カテゴリ・絞り込みは選択式。期限は日付入力 | TaskForm.tsx / CategoryManager.tsx / App.tsx |

## 3. 例外・トランザクション方針

- 対象が存在しない場合は Service で `NotFoundException` を送出し、`GlobalExceptionHandler` が404 + `{"message"}` に変換する
- バリデーション違反は同ハンドラが400 + `{"message"}` に変換する
- リクエスト本文が読めない場合(JSON不正、`priority` にenum外の値、`dueDate` が日付として不正など。`HttpMessageNotReadableException`)も同ハンドラが400 + `{"message"}` に変換する
- タスクに存在しないカテゴリIDを指定した場合は Service で `BadRequestException` を送出し、同ハンドラが400 + `{"message"}` に変換する
- カテゴリ名が重複する場合は Service で `ConflictException` を送出し、同ハンドラが409 + `{"message"}` に変換する
- カテゴリ削除時は、`TaskRepository.clearCategory` で該当タスクのカテゴリを外してから削除する(DBの `ON DELETE SET NULL` と同じ結果。同じトランザクション内で読み込み済みのタスクが削除済みカテゴリを参照し続けないよう、JPA側でも明示的に外す)
- クエリパラメータの型不一致(`sort` にenum外の値など。`MethodArgumentTypeMismatchException`)も同ハンドラが400 + `{"message"}` に変換する
- 「今日」は `Clock` Bean(`ClockConfig`)から取得する。テストでは固定日付の `Clock` に差し替えて期限切れ判定を検証する
- トランザクション境界は Service(クラスに `@Transactional(readOnly = true)`、更新系メソッドに `@Transactional`)

## 4. シーケンス図

タスク管理には複雑な処理(複数テーブル更新・条件分岐の多い計算等)が存在しないため、対象なし。
複数テーブルにまたがる更新や在庫計算のような処理を持つ機能では、その処理に限りシーケンス図を作成すること。
